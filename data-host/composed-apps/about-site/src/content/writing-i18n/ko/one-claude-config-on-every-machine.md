Claude Code는 Windows 클라이언트, Linux 클라이언트 및 RHEL 서버에서 실행됩니다. 각각은 전역 `CLAUDE.md`, `settings.json`, 일부 기술 및 명령어를 가지고 있으며, 각각은 약간 다른 세트로 발전해왔습니다. 이전의 해결책은 수동으로 복사하거나, 누군가 실행을 잊지 않고 실행할 때 파일을 밀어내는 Ansible 역할을 사용하는 것이었습니다. 하지만 이 방법은 한 대의 기계에서 이루어진 수정이 다른 기계로 돌아가지 않는 경우를 알아차리지 못했습니다.

## 기술의 시장

Claude Code는 플러그인을 시장에서 설치할 수 있으며, 시장은 단순히 플러그인을 나열하는 매니페스트가 있는 git 저장소일 뿐입니다. 2026-09-18에 개인 저장소가 하나가 되었습니다. 이제 이 시장은 다섯 개의 플러그인을 나열하고 있습니다:

- **workshop**: 이 사이트의 물리적 계획에 뒤따르는 build-plan 및 shopcad-model 기술;
- **homelab-ops**: homelab 대규모 컴퓨팅 클러스터에 LLM 작업을 제출하는 기술;
- **gpu-llm**: 게임용 GPU에서 수요에 따라 로컬 모델을 실행하기 위한 기술과 MCP 서버;
- **docs-tools**: Mermaid 다이어그램과 Obsidian 마크다운;
- **config-sync**: 나머지 모든 것을 최신 상태로 유지하는 플러그인.

대부분은 dotfiles 저장소에 있는 느슨한 기술로 시작했습니다. gpu-llm 플러그인은 한 대의 기계에만 존재했으며, 이 커밋은 아직도 푸시되지 않았습니다. 이 플러그인은 해당 체크아웃에서 시장으로 끌어들여졌고, 이미 드리프트된 IP 주소 대신 호스트의 DNS 이름을 통해 접근하도록 변경되었습니다.

## 두 가지 진실의 출처

dotfiles 저장소는 파일의 진실 출처입니다: 전역 `CLAUDE.md`, `settings.json`, 플러그인이 아닌 기술, 명령어. 시장은 플러그인의 진실 출처이며, 플러그인 변경은 버전을 업데이트함으로써 전달됩니다. 프로젝트별 메모리, `settings.local.json`, 자격 증명 및 캐시는 절대 변경되지 않습니다.

## config-sync

2026-09-19에 작성된 config-sync 플러그인은 bash 스크립트와 `SessionStart` 훅입니다. 각 세션 시작 시마다 추적되는 모든 항목의 해시를 생성하고 안전하게 적용합니다. 네트워크 작업(도트파일 체크아웃을 빠르게 전진시키기, 시장 업데이트, 나열된 모든 플러그인을 설치하거나 업데이트)은 하루에 최대 한 번만 발생합니다. 모든 것이 동기화되면 아무것도 출력하지 않습니다. 결정이 필요한 경우 `config-sync:`로 시작하는 줄을 출력하고, 동일한 플러그인의 기능이 Claude에게 이를 읽고 해결하는 방법을 알려줍니다.

안전하게 만드는 부분은 각 항목에 대해 마지막으로 적용된 해시를 저장하는 작은 상태 파일입니다. 이는 모든 비교를 세 가지 요소를 고려한 비교로 바꿉니다:

- 저장소가 이동했지만 로컬 복사본은 이동하지 않았다면: 조용히 적용합니다;
- 로컬 복사본이 이동했지만 저장소는 이동하지 않았다면: 보고하고 절대 덮어쓰지 않습니다. `push`는 편집 내용을 저장소로 되돌려 보내 다른 머신들이 이를 반영하도록 합니다;
- 둘 다 이동했다면: 충돌을 보고합니다. `--force`는 `apply` 또는 `push`에서 승자를 결정합니다.

`settings.json`는 키 순서를 무시한 JSON으로 비교되므로, 파일의 순서가 바뀌었어도 편집으로 간주되지 않습니다.

스크립트의 표면은 작습니다:

```
config-sync.sh status              # what differs, changes nothing
config-sync.sh apply [--force]     # pull, apply safe updates, update plugins
config-sync.sh push [-m msg]       # fold local edits back, commit, push
config-sync.sh diff <key>          # installed vs repo for one item
```

새로운 기계에서 부트스트랩은 두 줄입니다. 시장에 등록하고 config-sync를 설치한 후 재시작합니다. 첫 번째 세션의 훅은 dotfiles 저장소를 복제하고 전역 설정과 다른 네 개의 플러그인을 설치합니다. Windows는 Git Bash에서 이를 실행합니다.

테스트는 네트워크 없이 스텁된 `claude` 이진 파일과 함께 임시 홈 디렉토리 및 dotfiles 저장소에 대해 15개의 점검을 수행합니다. 첫 번째 실제 기계에서 `status`은 추적된 9개 항목 모두가 이미 단계에 있다고 판단했고, 첫 번째 `push`는 전역 `CLAUDE.md`의 새로운 섹션을 저장소로 다시 가져왔습니다.

## 후에 리뷰 봇

2026-09-24에 GitHub Action이 추가되어, 드래프트가 아닌 모든 pull request를 검토하고, 헤드 커밋에 승인 또는 변경 요청 판정을 고정하며, 깨끗한 pull request는 병합합니다. 이 봇은 헤드가 이동하지 않았고, `no-automerge` 라벨이 없으며, 워크플로우 또는 플러그인 디렉토리 아래의 변경이 없는 경우에만 병합합니다. 첫 번째 버전은 Claude로 검토했고, 같은 날 밤에 NanoClaw 편대의 무료 로컬 모델로 검토를 이전하여 LAN 내에서 유지하도록 했습니다. 봇은 자신의 워크플로우 디렉토리에 대한 변경을 병합하지 않기 때문에, 이를 추가하는 pull request는 인간이 병합해야 했습니다.

## 작동하지 않은 사항

- **Push-only Ansible role.** 이 역할은 대체 수단으로 유지되지만, 설정을 원격으로 푸시하는 경우 원격에서 이루어진 편집은 확인할 수 없다. 세션 시작 시에는 끌어올 수 있다.
- **플러그인을 설치하는 과정.** Claude Code의 자동 모드는 스크립트와 훅 파일을 플러그인 디렉터리에 쓰는 것을 거부하고, 이는 자가 수정으로 간주되었다. 다른 위치에 임시로 배치하고 그 후에 복사하는 것은 허용되었다. 리뷰 봇은 자신의 병합 스크립트("리뷰 없이 병합")에 동일한 문제를 겪었으며, 소유자가 자동 모드 외부에서 승인한 후에야 작성되었다.
- **`/tmp`의 테스트 스텁.** `/tmp`은 메인 서버에서 `noexec`에 마운트되어 있기 때문에, 거기서 배치된 스텁 바이너리는 무시되고 실제 바이너리가 실행된다. config-sync의 경우 스텁은 `sh`을 통해 실행된다. 리뷰 봇의 경우, 테스트는 실제 GitHub CLI에 도달했고 422 오류를 받았으며 아무것도 게시하지 않았다. `gh`는 이제 쉘 함수로 스텁 처리된다.

## 이어지는 내용

전역 편집은 이제 하나의 경로만 있다: 어떤 머신에서든 `push`에서 편집하고 나머지는 다음 세션 시작 시에 수렴한다. 새로운 추적 파일은 스크립트에서 하나의 사례로 나타나고 버전 업데이트가 필요하다. dotfiles 저장소에 있는 플러그인으로 이전된 스킬의 복사본은 여전히 존재하며, 모든 머신이 config-sync를 실행할 때마다 한 번씩 출력된다.
