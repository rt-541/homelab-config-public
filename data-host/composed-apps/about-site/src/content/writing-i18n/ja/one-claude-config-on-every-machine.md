Claude Code は Windows クライアント、Linux クライアント、RHEL サーバーのすべてで実行されます。それぞれにグローバル `CLAUDE.md`、`settings.json`、いくつかのスキルとコマンドがあり、それぞれがやや異なるセットに進化してきました。古い対処法は手動でのコピー、または誰かが実行を思い出したときにファイルをプッシュする Ansible ロールでした。どちらも、あるマシンで行った編集が他のマシンに反映されないことに気づいていませんでした。

## スキルのマーケットプレイス

Claude Code はマーケットプレイスからプラグインをインストールできます。マーケットプレイスとは、プラグインを一覧表示するマニフェストが含まれた git リポジトリのことです。2026-09-18 にプライベートリポジトリが一つこのようなマーケットプレイスになりました。現在、5つのプラグインを一覧表示しています：

- **workshop**: このサイトの物理的なプランに背後にある build-plan と shopcad-model スキル；
- **homelab-ops**: ホメラボ艦隊に LLM ジョブを送信するスキル；
- **gpu-llm**: ゲーミング GPU 上でオンデマンドのローカルモデルを実行するためのスキルと MCP サーバー；
- **docs-tools**: Mermaid 図と Obsidian Markdown；
- **config-sync**: 他のすべてを最新に保つプラグイン。

これらの多くは、ドットファイルリポジトリ内にあったスキルから始まりました。gpu-llm プラグインは、一度もプッシュされなかったコミットの中に存在していました。このチェックアウトからマーケットプレイスに引き込まれ、IP アドレスではなく DNS 名でホストに到達できるように変更されました。

## 2つの真実の情報源

ドットファイルリポジトリはファイルの真実の情報源です：グローバル `CLAUDE.md`、`settings.json`、プラグインでないスキル、コマンド。マーケットプレイスはプラグインの真実の情報源であり、プラグインの変更はバージョンを上げることによって配信されます。プロジェクトごとのメモリ、`settings.local.json`、資格情報、キャッシュは一切変更されません。

## config-sync

2026-09-19に構築されたconfig-syncプラグインは、bashスクリプトと`SessionStart`ハックの組み合わせです。各セッションの開始時に、追跡されているすべてのアイテムのハッシュを計算し、安全に適用可能なものを適用します。ネットワーク関連の作業（dotfilesのチェックアウトをファストフォワード、マーケットプレイスを更新、リストされているすべてのプラグインをインストールまたは更新）は、最大24時間に1回行われます。すべてが同期されている場合、何も出力しません。何か決定が必要な場合は、`config-sync:`から始まる行を出力し、同じプラグイン内のスキルがClaudeにそれらを読み取り、解決する方法を教えるようにします。

安全にするための仕組みは、各アイテムに最後に適用されたハッシュを保持する小さな状態ファイルです。これにより、すべての比較は三つのケースに分類されます：

- レポジトリが更新され、ローカルコピーは更新されていない：静かに適用します；
- ローカルコピーが更新され、レポジトリは更新されていない：報告し、決して上書きしません；`push`は編集をレポジトリに戻すため、他のマシンがそれを取得します；
- 両方とも更新されている：競合を報告します；`--force`は`apply`または`push`で勝者を選定します。

`settings.json`は、キーの順序を無視してJSONとして比較されるため、ファイルの順序が変わっただけでは編集とはみなされません。

スクリプトの表面的な部分は小さく、

```
config-sync.sh status              # what differs, changes nothing
config-sync.sh apply [--force]     # pull, apply safe updates, update plugins
config-sync.sh push [-m msg]       # fold local edits back, commit, push
config-sync.sh diff <key>          # installed vs repo for one item
```

新しいマシンでブートストラップを行うには、2行で、マーケットプレイスを登録し、config-syncをインストールしてから再起動します。最初のセッションのフックは、dotfilesリポジトリをクローンし、グローバルな設定とその他の4つのプラグインをインストールします。Windowsでは、Git Bashの下で実行されます。

テストでは、一時的なホームとdotfilesリポジトリに対して15のチェックを行い、スタブ化された`claude`バイナリとネットワークなしで実行します。最初の実際のマシンでは、`status`は9つの追跡項目すべてを既にステップに進んでいると採用し、最初の`push`はグローバルな`CLAUDE.md`の新しいセクションをリポジトリに戻しました。

## 後日、レビュー・ボット

2026-09-24に、GitHub Actionが追加され、ドラフトでないすべてのプルリクエストをレビューし、ヘッドコミットに承認または変更要求の判定をピン留めし、クリーンなプルリクエストをマージします。このアクションは、ヘッドが動いていない、`no-automerge`ラベルがない、ワークフローまたはプラグインディレクトリ以下の変更がない場合にのみマージします。最初のバージョンではClaudeを使用してレビューを行いました。同日の夜に行われた後続の作業では、レビューをNanoClaw艦隊のローカルモデルに移し、それによりLAN内に保持されるようにしました。ボットは、自身のワークフロー・ディレクトリへの変更をマージしないので、このボットを追加するプルリクエストは、人間によるマージが必要でした。

## うまくいかなかったこと

- **プッシュ専用の Ansible ロール。** フォールバックとして保持されていますが、設定をプッシュして送信することはできません。遠方の端末で編集された内容は見えていないためです。セッション開始時にプルすることで確認できます。
- **プラグインを配置する。** Claude Code の auto モードでは、スクリプトやホークファイルをプラグインディレクトリに書き込むことを拒否し、自己変更とみなして警告を出しました。他の場所に一時的に配置し、それをコピーして配置する方法は許可されました。レビュー bot は、同じように「レビューなしでマージ」するスクリプトで壁にぶつかり、所有者が auto モードの外で承認した後にのみ書き込まれました。
- **`/tmp` におけるテストスタブ。** `/tmp` はメインサーバーに `noexec` としてマウントされています。そのため、そこに配置されたスタブバイナリは静かにスキップされ、実際のバイナリが実行されます。config-sync ではスタブは `sh` を経由して実行されます。レビュー bot に関しては、テストが実際の GitHub CLI に到達し、422 エラーを返され、何も投稿されませんでした。`gh` は今やシェル関数としてスタブ化されています。

## 進展する内容

グローバルな編集は今や1つのパスをとります：任意のマシンで編集を行い、`push` に変更を加え、他のマシンは次のセッション開始時に同期されます。新しい追跡ファイルはスクリプト内での1つのケースとバージョンアップの必要がある場合です。dotfiles レポジトリ内の、プラグインに移動したスキルのコピーはまだ残っており、各マシンが config-sync を実行するたびに反映されます。
