# Deep-page i18n Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Translate the four remaining content pages (experience, projects, gaming, maker) into the six site languages using the existing `data-i18n` + dictionary mechanism.

**Architecture:** No new machinery. Each page task adds its keys to `src/i18n/ui.ts` and tags its elements with `data-i18n`; the global apply-script in `BaseLayout` (already site-wide) does the swapping. Project-card bodies are the one structural change: they move into the dictionary and `ProjectCard` renders them via the swap mechanism.

**Tech Stack:** Astro 4, the existing `src/i18n/ui.ts` dictionary + `BaseLayout` apply-script, Tailwind.

**Reference spec:** `docs/superpowers/specs/2026-05-28-deep-page-i18n-design.md`

---

## Conventions used throughout

- **Dictionary additions:** add each key to all six language blocks in `src/i18n/ui.ts`. For page-static/frontmatter-sourced text, the `en` value may be omitted (the static markup already carries English; the apply-script falls back to it). For **project-card bodies**, include `en` too (they stop being rendered from markdown). Author ja/ko/zh/es/de following the existing `ui.ts` style and the spec's proper-noun policy (keep org names, game titles, cert names, tech/skill items, addresses, `RT-541`, the `@handle`, material, and slicer settings in English; keep proper nouns like Strixhaven/Azur inside translated prose).
- **English source of truth:** lives in the page `.astro` / collection frontmatter (and, for project bodies, the dictionary `en`).
- **Verification per task:** build succeeds; the new keys exist in all six languages with parity; English still ships in the static HTML; the new `data-i18n` attributes appear in the built page.
- **Read the file before editing it** so the `data-i18n` additions land on the exact existing elements.

The full key list per page is in the spec under "Per-page coverage" and "Key naming conventions"; each task below restates its keys with their English source text.
